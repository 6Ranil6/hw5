## Вход, обучение и ограничения

Взяты без изменения `train.pt` и `val.pt` из ДЗ 4: **896 train и 112 val**, маска `labels=-100` на промпте и паддинге, левый паддинг до кратного 128 при обучении, лимит 768. Источник полностью синтетический — литературные формы по текстовым описаниям модальностей. Никакие внешние медицинские данные не использованы; test-сплит не затрагивался.

Каждый вариант проходит одну полную эпоху: **112 шагов**, batch_size=1, grad_accum=8, lr=2e-4, r=8, alpha=16. Validation использует все 112 примеров, eval_batch_size=1. Python 3.12, PyTorch 2.9.1 закреплены в окружении. Итоговый численный режим — float32 и eager attention при обучении на Apple M2 Pro с 16 ГБ памяти; причины выбора и прерванные попытки описаны в `docs/runtime_notes.md`. `max_steps: null`; короткий smoke запуск отделён от полного обучения и не выдаётся за выполнение задания.

Первый вариант обучает LoRA на всех слоях, второй — только на слоях 14–27. В обоих случаях базовые веса заморожены. Packing не используется. Реальное качество литературных текстов не измеряется пятью промптами: это иллюстрации поведения на validation-вопросах. Тексты в сравнении — фактическая greedy-генерация, ответы вручную не заменяются. Оба варианта сравниваются по параметрам, времени, памяти и val loss в `docs/run_summary.md`.

## Воспроизведение

```bash
uv sync --locked
uv run dvc pull
uv run dvc repro
make test
make check
```

Для `dvc pull` сначала нужен отдельно переданный локальный remote. Архив `submission/dvc_remote.tar.gz` распаковывается из корня репозитория: `tar -xzf /путь/к/dvc_remote.tar.gz`. В `.dvc/config` URL `../dvc_remote` считается относительно `.dvc/`, то есть хранилище лежит внутри корня проекта.

При отсутствии архива скопируйте свои тензоры из ДЗ 4 в `data/tokenized/`, затем выполните полный расчёт:

```bash
uv run dvc repro
# Эквивалентные команды без DVC:
# make train
# make compare
```

Веса базовой модели требуются для обучения и инференса. При первом запуске они скачиваются из HuggingFace; последующие запуски допускают `HF_HUB_OFFLINE=1`. Ревизия Qwen3 и токенизатора закреплена в params; точные версии библиотек — в uv.lock. На CPU настройте `model.dtype: float32`; полный прогон будет значительно дольше. При изменении кода обучения, данных или конфигурации выполните новый `make train` / `dvc repro`: проверка отвергает устаревший отпечаток.

`make check` **не повторяет полное обучение**, но действительно запускает два отдельных обучения по три шага и проверку offline-загрузки адаптера. Не запускайте его одновременно с полным обучением на том же MPS-устройстве.

## Перенос адаптера

В папках `models/adapter_all_layers/` и `models/adapter_freeze14/` находятся матрицы LoRA, adapter_config, токенизатор, chat template и inference_config с исходными параметрами генерации. На другом компьютере **базовая модель должна быть доступна отдельно**, в том числе заранее в HF-кеше для offline-проверки. Сама папка адаптера не содержит базовые веса.

```bash
HF_HUB_OFFLINE=1 uv run python -m src.compare \
  --adapter-dir /путь/к/adapter_all_layers \
  --only-adapter --out /tmp/adapter_answers.json
```

Эта команда использует фиксированные промпты и режим генерации из params текущего проекта; для отдельного потребителя те же настройки сохранены в `inference_config.json` внутри экспортированной папки. Offline-проверка из `tests/check.sh` сравнивает пять ответов дословно.

## Файлы и сдача

- `data/tokenized/`: только входные train.pt и val.pt; исходные JSONL для обучения здесь не нужны.
- `models/`: экспортированные адаптеры с токенизаторами.
- `metrics/*.json`: фактические кривые, параметры, времена и ответы; по условиям **не входят в Git**, версионируются DVC.
- `docs/`: разбор ошибок, таблица измерений, график, сравнение, происхождение входа и логи проверок; входят в Git.
- `checkpoints/`: локальное восстановление полного обучения каждые 10 шагов; несовместимый отпечаток запрещает продолжение.
- `submission/`: видео, исходная запись вывода, архив DVC remote и отдельный smoke-эксперимент; передаются отдельно от Git.
